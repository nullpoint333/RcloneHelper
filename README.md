# RcloneHelper

一个使用 Avalonia UI 开发的 rclone 辅助工具，用于管理 WebDAV / FTP / SFTP / S3 等存储的挂载。

## 功能特性

- **多种存储类型**：WebDAV（Nextcloud / OwnCloud / SharePoint / Fastmail）、FTP、SFTP、S3（AWS / 阿里云 / 腾讯云 / Google / 自定义 Endpoint）
- **挂载管理**：单个挂载/卸载/编辑/删除，批量挂载/卸载，挂载状态实时显示，支持中途取消
- **只读查看模式**：编辑正在挂载的连接时自动进入查看模式，所有输入框只读；需要修改时点「卸载并编辑」
- **搜索与筛选**：按名称、类型、地址、挂载点搜索，并可在「全部 / 已挂载 / 未挂载」之间切换
- **连接测试**：保存前先做连通性预检（WebDAV 走 HTTP，FTP/SFTP/S3 走 TCP），避免创建出打不通的挂载
- **rclone 缓存管理**：缓存目录、缓存上限、占用统计、一键清理，避免缓存占满系统盘
- **代理支持**：http / https / socks5，可带认证；挂载与连接测试都会走代理
- **开机自启与静默启动**：开机自启时可直接最小化到托盘
- **主题切换**：深色 / 浅色主题，跟随设置保存
- **配置备份**：挂载配置导出为 JSON，可从备份导入（跳过同名连接）

## 系统要求

- Windows 10/11
- .NET 10.0 或更高版本
- rclone 已安装并在 PATH 中，或放在程序目录下
  - 程序通过 `rclone config create --obscure --non-interactive` 写入配置，建议使用 1.65+（1.70+ 更稳）；版本过旧可能不识别这些参数
- Windows 挂载需要 WinFsp

## 编译与运行

```bash
dotnet restore
dotnet build -c Release
dotnet run --no-build -c Release
```

> ⚠️ 开发时请使用 Release 配置：Debug 输出会被正在运行的 Debug 实例锁定，导致编译失败。

### 发布独立应用

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

## 使用说明

### 添加挂载

1. 点击右上角「添加挂载」
2. 选择类型并填写对应字段：
   - **WebDAV**：协议 / 主机 / 端口 / 路径 / 用户名 / 密码 / 服务商
   - **FTP / SFTP**：主机 / 端口 / 路径 / 用户名 / 密码
   - **S3**：服务商 / Access Key / Secret Key / 区域 / Endpoint / Bucket
   - **其他类型**：直接填写完整 URL
3. 选择挂载点、是否使用网络驱动器模式、是否随程序自动挂载
4. 可以先点「测试连接」确认网络与凭据，再保存

### 挂载 / 卸载

- 列表每行的图标依次是：挂载 ▶、取消挂载 ✕、卸载 ■、编辑、删除
- 顶部可一键「全部挂载」/「全部卸载」
- 删除前会二次确认；正在挂载的连接会先卸载再删除

### 后台上传与取消

rclone 使用写缓存（`--vfs-cache-mode writes`）时，复制大文件在资源管理器里会**立刻显示完成**，
真正的上传在后台继续。程序会把这段「看不见的传输」显示出来：

- 挂载行里显示「后台上传中 N 个文件 · X GB」，页面顶部也有汇总
- 需要中断时点该行的「取消上传」：
  1. 立即结束这个挂载的 rclone 进程（不再继续上传）
  2. 删除该连接在 VFS 缓存中尚未上传的数据（已经上传到远端的部分无法撤回）
  3. 自动重新挂载，盘符继续可用

> 只结束进程是不够的：rclone 下次挂载会自动续传缓存里的残留数据，所以必须同时清掉对应缓存。
> 数据量来自 `<缓存目录>/vfs/<连接名>`，每 2 秒刷新一次。

### 只读查看模式

编辑一个**正在运行**的挂载时会自动进入只读查看：名称、主机、端口、账号、路径等所有输入框都不可修改，但可以查看、复制。

需要修改时：

1. 在对话框底部点「卸载并编辑」，确认后程序会卸载该连接
2. 对话框切换为可编辑状态，修改完成点「保存」
3. 如需恢复挂载，重新点列表中的挂载按钮即可

> 这样设计是为了避免「改一个字段就必须先把挂载卸掉」的意外中断。

### rclone 缓存

rclone 的 VFS 缓存默认会写在系统盘，缓存较大时建议换到其他盘：

1. 打开「设置 → rclone 缓存」
2. 「缓存目录」选择目标目录（留空表示使用默认位置 `%APPDATA%\rclone\cache`）
3. 可选填写「缓存上限」，例如 `10G`、`500M`，留空表示不限制
4. 点「保存」，然后**卸载并重新挂载**连接才会生效

同一张卡片里还可以：

- 查看当前缓存占用大小（「重新统计」可刷新）
- 「打开文件夹」直接定位缓存
- 「清理缓存」删除缓存内容（有挂载在运行时会被拒绝，避免文件占用；不会影响远端文件）
- 「恢复默认」把缓存目录和上限还原

实现方式：程序在每次 `rclone mount` 时显式传入 `--cache-dir`（以及可选的 `--vfs-cache-max-size`），所以缓存位置与 rclone 自身的默认值无关，始终由这里决定。

### 开机启动与静默启动

- 「设置 → 通用」勾选「开机启动」会写入 Windows 启动项
- 勾选「静默启动」后，开机自启时直接最小化到托盘（手动启动仍会显示窗口）

## 配置文件位置

```
%APPDATA%\RcloneHelper\
├── mounts.json      # 挂载配置（密码使用 DPAPI 加密）
├── settings.json    # 应用设置（主题、代理、缓存目录等）
└── log\             # 运行日志，保留 7 天
```

rclone 自身的配置文件位于 `%APPDATA%\rclone\rclone.conf`，可以在「Rclone 管理」页直接打开所在目录。

## 注意事项

1. 首次使用前请确认 rclone 与 WinFsp 已正确安装（「Rclone 管理」页会显示依赖状态）
2. 某些操作（创建网络驱动器、修改系统盘符）可能需要管理员权限
3. 关闭窗口默认最小化到托盘。从托盘「退出」后，已挂载的 rclone 进程会继续运行；下次启动程序会自动扫描并接管这些挂载
4. 挂载参数使用 `--vfs-cache-mode writes`，写入会立即刷新到远端
